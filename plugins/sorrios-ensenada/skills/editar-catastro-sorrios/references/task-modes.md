# Modos de tarea

## Consulta puntual

Lee `project/00_CONTROL/proyecto.yaml`, `project/00_CONTROL/estado.yaml` y la fuente precisa. No abras el Manual salvo que la pregunta dependa de un criterio. Drive solo se consulta si hace falta el PDF. No escribas.

## Edición de unidad

Confirma que `operation.status` sea `clean`, que la unidad actual coincida con `project/00_CONTROL/unidades.yaml` y que la anterior esté cerrada. Lee el Manual, `workspace-contract.md`, `editorial-procedure.md`, `github-operations.md` y `pdf-access.md`. Lee visualmente la unidad del PDF y prepara la operación completa antes de publicar un único commit atómico.

## Auditoría

Lee `workspace-contract.md` y `document-schemas.md`. Comprueba estructura, versiones, 35 unidades, estado, secciones obligatorias, operaciones, ausencia de PDF en GitHub y coherencia de autoridades. Informa de los fallos. Corrige solo si el usuario lo pide.

## Cambio metodológico

Distingue criterio nuevo de aplicación de uno vigente. Lee el Manual, `workspace-contract.md`, `document-schemas.md` y `github-operations.md`. Si hace falta un criterio nuevo, prepara el cambio y su efecto. Espera aprobación antes de publicar.

## Estudio histórico

No escribas mientras `historical_study_enabled` sea falso. Cuando se active, usa solo unidades validadas como base documental y sigue el mismo protocolo Git para cualquier cambio multiarchivo.
